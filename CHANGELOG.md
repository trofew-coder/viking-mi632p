**Дата и время:** 2026-11-27 (Европа/Москва) — восстановление после тестовой сессии

**Задача:** Восстановление боевого кода, очистка от тестовых файлов, фикс CH340

**Изменённые файлы:**
- `firmware/mega2560/src/main.cpp` — восстановлена полная боевая прошивка (Timer1 ESC + сервы)
- `firmware/mega2560/src/test_main.cpp` — УДАЛЁН (мешал сборке)
- `firmware/mega2560/src/main_fast.cpp` — УДАЛЁН (временный файл)
- `pi/web_control.py` — синхронизирована с `Репозиторий viking-mi632p` (содержит `_bladeOn`)

**Суть изменений и статус:**

### 1. Восстановлен боевой main.cpp
**Проблема:** После тестовой сессии в main.cpp оставался минимальный тестовый код (~34 строки), а рядом лежал `test_main.cpp`.

**Решение:** Полностью восстановлена боевая прошивка с:
- Timer1 direct для ESC (пины 11/12, без Servo library)
- Софт-сервы на пины 4/5 (Timer2)
- Чистые C-строки `char rxBuf[64]` вместо `String`
- Команда `ESC;US_L;US_R` для ручной калибровки
- Все функции: DRV, BLD, S1/S2, R1/R2, TIME, ROT, BTN, RST
- Обновлённый LCD с телеметрией

**Размер прошивки:** ~13 284 байт (5.2% Flash), RAM ~12.5%

### 2. Удалены мусорные файлы
- `test_main.cpp` — временная тестовая прошивка (мешала сборке PlatformIO)
- `main_fast.cpp` — временный файл предыдущей попытки

### 3. Синхронизация web_control.py
- Скопирована версия из `Репозиторий viking-mi632p`
- Содержит исправление `_bladeOn` вместо конфликта `blade_on`
- Содержит `/api/esc` endpoint и ESC панель в HTML

### 4. FIX: CH340 не перезагружается от stty
**Проблема:** `stty -F /dev/ttyUSB0 115200` на CH340 дергает DTR → Mega перезагружается.

**Решение для будущих сессий:**
- НЕ использовать `stty` + `echo` для проверки UART
- Использовать Python pyserial: `serial.Serial(port, baud, dsrdtr=False)`
- При зависании: программный сброс через `usbreset` или перепривязку драйвера

## Запись от 2026-11-27

**Изменённые файлы:**
- `firmware/mega2560/src/main.cpp` — полная перепись
- `firmware/remote_d1mini/src/main.cpp` — неблокирующий HTTP
- `pi/web_control.py` — исправление blade_on, добавление ESC API
- `docs/PINOUT.md` — новая распиновка без конфликтов
- `docs/PROTOCOL.md` — добавлена команда ESC

**Суть изменений и статус:**

### 1. Arduino Mega (main.cpp) — полная перепишка
**Проблема:** `String rxBuffer = ""` в loop при быстрых командах фрагментирует память. На Mega 2560 всего 2 КБ ОЗУ → со временем висяк.

**Решение:**
- Убран `String` → чистые C-строки `char rxBuffer[64]` с ручным управлением размером
- `processCommand()` принимает `const char*`, парсинг через `strchr()`/`strtok()` — без временных `substring`
- Переход на BLDC ESC через Servo library (1000–2000 мкс)
- ESC в нейтраль (1500 мкс) при старте и при аварии — безопасное состояние
- HEARTBEAT_TIMEOUT увеличен с 300 до 1000 мс
- Пины перераспределены — **конфликты серв/реле убраны**: ESC(8/9), сервы(11/12), реле(47/48), нож(49)
- 2 сек задержка при старте для калибровки ESC

### 2. D1 mini — неблокирующий HTTP
**Проблема:** `sendState()` блокирует loop на 1.5+ секунды (http.setTimeout(1500)). Пока POST висит, импульсы энкодера теряются.

**Решение:**
- `trySendState()` с throttle 200 мс — не блокирует loop
- Если POST не успел — игнорируем, отправим в следующей итерации
- Энкодер обрабатывается каждый loop, импульсы не теряются

### 3. web_control.py — исправление blade_on
**Проблема:** `blade_on` — одновременно метод и флаг `self.blade_on`. После первого вызова `blade_off()` метод перезаписывается в `False`.

**Решение:**
- Флаг переименован в `self._bladeOn` (приватный)
- Метод `set_blade(on)` устанавливает флаг + шлёт команду
- Методы `blade_on()` / `blade_off()` вызывают `set_blade()`
- API `/api/esc` для ручной калибровки ESC из веб-интерфейса
- В HTML добавлена панель ESC калибровки (два числовых поля + кнопка «Применить»)

**Команды для деплоя на Pi:**
```bash
sudo systemctl stop viking.service
mkdir -p ~/backup
cp ~/web_control.py ~/backup/web_control.py.20261127
cd ~/viking_project && cp src/main.cpp ~/backup/main.cpp.20261127
# ... записать новые файлы на Pi (scp или Desktop Commander)
cd ~/viking_project && pio run --target upload --upload-port /dev/ttyUSB0
cd ~/viking_remote && pio run --target upload --upload-port /dev/ttyUSB1
sudo systemctl start viking.service
journalctl -u viking.service -f --no-pager
```
